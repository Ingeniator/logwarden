# logwarden v0.5.0

**Status:** Released 2026-11-18 · tag v0.5.0.

Make good logs the easy path: one call sets up logging that passes the standard, helpers
make failure logs easy to write and to test, and the check can prove that every upstream's
failure path was exercised.

## What's new

- **`logwarden.logging.configure()`** (install `logwarden[structlog]`). The reference
  structlog + stdlib setup from the standard, in one call:

  ```python
  from logwarden.logging import configure
  log = configure(service_name="billing-api", service_version="1.4.2",
                  environment="production")
  ```

  - Every line is one JSON object on stdout, including stdlib and third-party loggers.
    Third-party lines get the constant event `library_log`, with their text in
    `log.record.original`.
  - Adds `timestamp` (ISO-8601 UTC), `level`, `logger`, `service.name`, `service.version`,
    `deployment.environment.name`, and `trace_id`/`span_id` from the active OpenTelemetry
    span when the OTel API is installed.
  - Exceptions (`exc_info=True`, `log.exception`) become `exception.type`,
    `exception.message` and `exception.stacktrace`.
  - Redacts secrets: fields named like `password`/`token`/`authorization`, and tokens, API
    keys, credentials in URLs, emails and card numbers inside values. `keep=` exempts
    fields that must be logged.
  - Noise control: chatty loggers (`urllib3`, `httpx`, `httpcore`, `botocore`, …) at
    `WARNING`; health/metrics paths (`/health`, `/healthz`, `/livez`, `/readyz`, `/ready`,
    `/metrics`) dropped from access logs and from events with that `http.route`/`url.path`.
  - Arguments fall back to `OTEL_SERVICE_NAME`, `SERVICE_VERSION`, `DEPLOYMENT_ENVIRONMENT`
    and `OTEL_RESOURCE_ATTRIBUTES`. A missing name/version or an undocumented environment
    (`dev`, `prod`) raises `ValueError` at startup instead of producing bad logs.
  - `json=False` gives human-readable console output for local development.
- **Helpers for failure logs** in `logwarden.logging`:
  `extract_error_code(response)`, `extract_error_message(response, limit=500)` (OpenAI,
  Anthropic, FastAPI and generic `{code, message}` bodies, httpx/requests responses, dicts
  or text) and `scrub(text, limit=500)` (redaction + truncation).
- **Test helpers** in `logwarden.testing`: `capture()` collects the JSON lines the service
  writes during a block, `assert_failure_logged(records, event, **fields)` checks a
  failure line exists and says what failed, and `assert_logs_clean(records)` runs the full
  logwarden check on them.
- **New rule `adr_upstream_failure_coverage` (§10).** With
  `upstreams = ["api.openai.com", ...]` in the config, `check` fails when the run has no
  warning/error (or `*_failed`) line with `server.address` equal to an upstream, i.e. no
  test exercised that upstream's failure path. Findings for the whole run have `line: null`.
  (The roadmap said `upstreams.yaml`; a list in the existing config needs no YAML parser.)

## Changes

- `adr_failure_context` doesn't apply to `library_log` lines: a third-party library's
  warning can't be given failure context by the service. Its other rules still apply.
- The standard's reference setup section now shows `configure()`; the hand-written
  processor list stays as the explanation.

## Fixes

- **No git clone on every check.** Weaver used to clone the OTel semantic-conventions
  repository from GitHub on every run. That made each check depend on the network and
  failed whenever the clone did ("Failed to consume the pack sent by the remote" broke
  the test run while v0.5.0 was being built). logwarden now downloads the pinned release
  archive once, checks its SHA-256, caches it next to Weaver (`LOGWARDEN_CACHE`), and points
  the registry at the local copy. After the first run, checks work offline.
  `LOGWARDEN_SEMCONV` points at a local semconv `model` directory instead.

## Breaking changes

None. The core install still has no dependencies besides `tomli` on Python 3.10.

## Upgrading from v0.4.0

```bash
uv add logwarden[structlog]==0.5.0           # runtime dependency now, for configure()
```

Replace the project's logging setup with `configure(...)`, run uvicorn with
`log_config=None` so it doesn't reinstall its own handlers, and list upstreams in
`[tool.logwarden] upstreams = [...]`. CI: `uses: Ingeniator/logwarden@v0.5.0`.
Claude Code: `/plugin update logwarden@logwarden`.
