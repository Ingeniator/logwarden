# logwarden v0.10.0

**Status:** Planned.

Check metrics against a standard, as logwarden does for logs. The
[metrics standard](../metrics-standard.md) adopts the OpenTelemetry metric semantic conventions
and adds what they leave open: label rules shared with logs, cardinality budgets, sensitive
data and resource identity. The engine stays the same: OTel Weaver live-check with logwarden's
Rego rules. Baselines, `--compare`, SARIF, reports, the Action and MCP work for metrics with no
new setup.

## Spike results (2026-11-21)

Weaver v0.28 `live-check` with semconv 1.45, fed six metrics from the OTel Python SDK over
OTLP gRPC: one correct, five with typical mistakes
([`tests/data/metrics_spike/emit.py`](https://github.com/Ingeniator/logwarden/blob/main/tests/data/metrics_spike/emit.py)).

| Mistake | Found by | Finding |
|---|---|---|
| Custom name where semconv has one (`api_latency_ms`) | Weaver | `missing_metric` (no hint to the semconv name) |
| Semconv metric with unit `ms` instead of `s` | Weaver | `unit_mismatch` |
| Duration as a counter instead of a histogram | Weaver | `unexpected_instrument` |
| Label `status` | logwarden Rego, unchanged | `adr_banned_synonym` |
| Email address in a label value | logwarden Rego, unchanged | `adr_sensitive_data` (message says "don't log it") |
| 300 distinct `user.id` values on one counter | nothing | `user.id` is valid semconv, so nothing flags it |
| `payments_total_count` (suffixes in the name) | Weaver, partly | only `missing_metric`, no naming hint |
| Missing resource attributes | nothing | resources aren't checked |

Also found:
- Weaver accepts metric samples from a JSON file (`--input-source file`), the way logwarden
  already feeds it logs. Scraped Prometheus text can be converted to samples, with no OTLP
  listener needed.
- Weaver's OTLP listener is gRPC only; `logwarden capture` is OTLP/HTTP.
- One finding per data point: 300 series gave 300 identical findings. Findings need grouping
  per metric and attribute.

So the existing pipeline carries over. New work: input conversion, cardinality, resource
checks, naming hints and grouping.

## What's new

- **`logwarden check --signal metrics`** checks metrics with the same options, exit codes and
  outputs as logs (`--json`, `--sarif`, `--markdown`, `--html`, `--metrics`, `--baseline`,
  `--compare`, `--snapshot`). Inputs, detected automatically:
  - Prometheus or OpenMetrics text, such as a saved `curl :9464/metrics`. Names are translated
    back to OTel names (`http_server_request_duration_seconds` → `http.server.request.duration`,
    unit `s`; `_total`, `_ratio` and unit suffixes per the OTel compatibility spec). Dotted
    UTF-8 names from Prometheus 3 are read as they are.
  - OTLP JSON metrics, as written by `logwarden capture`.
- **`logwarden capture` receives metrics.** `/v1/metrics` (protobuf and JSON) next to
  `/v1/logs`; metrics go to their own output file. `capture -- pytest` checks the metrics a
  test run emits.
- **Rules.** Weaver's `missing_metric`, `unit_mismatch`, `unexpected_instrument` and
  `required_attribute_not_present` get hints and `docs/rules.md` entries. The label rules
  (`adr_banned_synonym`, `adr_semconv_prefix`, `adr_sensitive_data`, `missing_attribute`) run
  on metric attributes unchanged; their messages no longer say "log". New:
  - `adr_metric_name`: units or `_total`/`_count` in an OTel name; a custom name that is close to
    a semconv metric names the semconv metric.
  - `adr_metric_cardinality`: an attribute from the unbounded list (IDs, emails, `url.full`,
    `url.path`, …) on a metric, or a metric over its series budget (default 1,000 per
    service, `[metrics] series_budget` in the config, per metric if needed).
  - `adr_missing_required` also checks the resource of every metric.
  - `adr_metric_required`: a metric listed in `[metrics] required` is absent from the run.
- **One finding per metric and attribute,** with the number of series, instead of one per
  data point.
- **Domain metrics** are declared in `logwarden-fields.yaml` (a `metrics:` section next to the
  fields), with instrument, unit and attributes, and checked like semconv metrics.
- **MCP:** `check_logs` accepts `signal: "metrics"`; `get_standard` can return the metrics
  standard.

## Breaking changes

None. Rule messages for `adr_sensitive_data` change wording ("telemetry" instead of "logs");
ids, `--json` keys and exit codes don't change.

## Open questions

- `check --signal metrics` or a separate `logwarden metrics check`? Planned: the flag, so every
  existing option and the Action input work as they are; detecting Prometheus text
  automatically makes it optional for files.
- The series budget default (1,000) comes from common vendor guidance; it may move after trying
  it on real services.
