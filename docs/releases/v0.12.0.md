# logwarden v0.12.0

**Status:** Planned, **conditional.** Starts only if the [v0.11.0](v0.11.0.md) trial says
*go*, and its scope is cut to what the trial found useful. If the trial says *no-go*, this
version is dropped.

**Outcome: metrics checked in the same everyday workflow as logs.** A team that already runs
logwarden on its logs in CI or on a schedule adds metrics with one option. The findings appear
in the same merge request, report and dashboard, and existing metrics debt doesn't block
anyone, thanks to the baseline.

## What's new

- **`--signal metrics` is stable.** Rule ids, `--json` keys and exit codes for metrics become a
  public interface, like those for logs.
- **More inputs.** OTLP JSON metrics, and `logwarden capture` receives `/v1/metrics`
  (protobuf and JSON) next to `/v1/logs`, so `capture -- pytest` checks the metrics a test run
  emits.
- **More rules.**
  - `adr_metric_name`: units or `_total`/`_count` in an OTel name; a custom name close to a
    semconv metric names the semconv metric.
  - `adr_missing_required` also checks the resource of every metric (`service.name`,
    `service.version`, `deployment.environment.name`).
  - `adr_metric_required`: a metric listed in `[metrics] required` is missing from the run.
  - Per-metric series budgets in `[metrics] series_budget`.
- **Domain metrics** declared in `logwarden-fields.yaml` (a `metrics:` section), with instrument,
  unit and labels, and checked like semconv metrics.
- **Same workflow as logs.** `--baseline`, `--compare`, `--snapshot`, `--html`, `--sarif` and
  `--codequality` for metrics. The GitLab template gets `LOGWARDEN_SIGNAL`, and the scheduled job
  from v0.9.0 can check saved `/metrics` output too. The Action gets a `signal` input; MCP
  `check_logs` accepts `signal: "metrics"`; `get_standard` can return the metrics standard.
- Rule messages for `adr_sensitive_data` say "telemetry" instead of "logs".

## Breaking changes

None. Ids, `--json` keys and exit codes for logs don't change. Metrics rules from v0.11.0 may
be renamed once here, while they're still experimental, and the notes will list any rename.
