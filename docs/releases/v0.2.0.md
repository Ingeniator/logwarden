# logwarden v0.2.0

**Status:** Released 2026-11-17 · commit `6740972`

This version makes logwarden usable by other projects and AI agents: findings point to
the exact line and say how to fix it, and logs can be captured from tests.

## What's new

- **Project fields file.** Projects list their own fields in `logwarden-fields.yaml`,
  which is picked up automatically (or passed with `--fields`), and pin logwarden in only
  one place.
- **Findings an agent can act on.** Each finding has the input line number, the rule, the
  field and a fix hint. `--json` returns everything in machine-readable form. A field
  flagged as a banned synonym is no longer also reported as unknown.
- **Messages that give the fix.** `status` → "use http.response.status_code", `http_route`
  → "probably 'http.route'".
- **Reads stdin.** `… | logwarden check -`. Lines that aren't JSON are counted as skipped.
- **New commands.** `logwarden rules [id]`, `logwarden init [--agent]`, `logwarden setup`.
  Weaver downloads itself on first use.
- **pytest plugin** `logwarden-pytest`: `LOGWARDEN_CAPTURE=logs.jsonl pytest`.
- **MCP server** `mcp/server.py` with `check_logs`, `explain_rule`, `list_rules` and
  `get_standard`.
- **Docs** `docs/standard.md`, `docs/rules.md`, `docs/integration.md`. `AGENTS.md`, a
  skill, and an `AGENTS.md` snippet for other projects.
- **Action.** New `fields` and `fail` inputs, plus a job summary.

## Upgrading from v0.1.0

- Change `uses: Ingeniator/logwarden@v0.1.0` to `@v0.2.0`.
- Rule messages now start with `§N:` instead of `ADR-0001 §N:`. Rule ids are unchanged.
