# logwarden v0.7.0

**Status:** Planned.

Review: show what a change does to the logs. Compare a run with the base branch, read the
result as an HTML report or a pull-request comment, and keep a catalog of the events a
service emits.

## What's new

- **Snapshots and comparison with the base branch.**

  ```bash
  logwarden check logs.jsonl --snapshot base.json          # on main: save what this run found
  logwarden check logs.jsonl --compare base.json           # on a branch: what's new, what's fixed
  ```

  - A snapshot records each finding and each event name seen, with counts. Findings are
    matched by the same key as the baseline (rule, field, logger, event), not by line
    number, so a moved line isn't "new".
  - `--compare` adds a `compare` key to the `--json` result:
    `{base, new, fixed, unchanged, new_findings, fixed_entries, new_events, gone_events}`.
    The text output gets one line: `compared with base.json: 2 new, 1 fixed`.
  - `--compare` also accepts a baseline file, since both list findings the same way.
  - `--compare` only reports. The exit code still comes from the violations after `disable`
    and the baseline. To fail only on new findings, use the baseline, as before.
- **HTML report: `check --html report.html`.** One self-contained file (no scripts, no
  external CSS or fonts) that works offline and as a CI artifact. It contains:
  - the totals;
  - the comparison, when there is one;
  - one section per rule with its title, fix hint and a link to `docs/rules.md` at this
    version;
  - every finding with its line number;
  - the event catalog of the run.

  It uses light and dark themes. Everything is HTML-escaped, and like the text output it
  never shows logged values, only messages, which never contain them. `-o DIR` now also
  writes `report.html`, `report.md` and `snapshot.json`.
- **Markdown summary and PR comment.** `check --markdown FILE` writes a short summary:
  - status and counts;
  - new and fixed findings when comparing;
  - a table by rule with fix hints;
  - the first new findings;
  - new event names.

  It stays under GitHub's comment size limit. The GitHub Action uses it:

  ```yaml
  permissions:
    contents: read
    pull-requests: write        # only for comment: "true"
  steps:
    - uses: Ingeniator/logwarden@v0.7.0
      with:
        logs: logs.jsonl
        comment: "true"         # one comment per PR, updated on each push
  ```

  New Action inputs, each with a default that keeps the current behaviour:
  - **`compare`** (default `auto`). On a push, the Action saves the run's snapshot to the
    Actions cache. On a pull request, it restores the base branch's latest snapshot and
    compares with it. GitHub lets a pull request read the base branch's cache, so no
    artifact juggling or extra tokens are needed. It can also be a snapshot path, or
    `"false"` to turn comparing off.
  - **`comment`** (default `"false"`). Posts the Markdown summary as a single comment and
    updates it on later pushes. It finds that comment by a hidden marker. Without write
    permission (pull requests from forks), it prints a warning instead of failing the step.
  - **`upload`** (default `"true"`). Uploads `logwarden.report/` (HTML, Markdown, JSON,
    snapshot) as the artifact `logwarden-report`.

  The job summary now shows the Markdown summary instead of the plain text.

  On other CI systems, `--snapshot`, `--compare`, `--markdown` and `--html` work the same
  way (`docs/integration.md` shows GitLab).
- **Event catalog.**
  - **`logwarden catalog logs.jsonl`** lists every event name in a run. For each one it
    shows the count, levels, loggers and fields, and the first line where it appears.
    Use `--json` for machine-readable output and `--markdown` for docs.
  - `catalog logs.jsonl -o logwarden-events.toml` writes a catalog file to commit and
    describe:

    ```toml
    [events.order_imported]
    description = "An order file was parsed and stored."
    levels = ["info"]
    ```

    Running it again adds new events and keeps existing descriptions. Events that a run
    didn't produce are kept too, because one run rarely covers every path.
  - **New rule `adr_event_catalog` (§4).** With `events = "logwarden-events.toml"` in the
    config, `check` reports each event that isn't in the catalog. It runs only when a
    catalog is configured, like `upstreams`. Event names then stay a reviewed list, so
    dashboards and alerts that match on them don't silently break.
  - The catalog is TOML, so it needs no new dependency: Python 3.11+ reads it natively,
    and `tomli` already covers 3.10.

## Breaking changes

None. The new `--json` key and the Action inputs are additions, and exit codes don't
change. The core install still has no dependencies besides `tomli` on Python 3.10.

## Upgrading from v0.6.0

Bump `uses: Ingeniator/logwarden@v0.7.0`. Comparison starts working once one push to the
base branch has saved a snapshot. Add `comment: "true"` and `pull-requests: write` for the
PR comment. To start a catalog, run `logwarden catalog logs.jsonl -o logwarden-events.toml`,
fill in the descriptions, then set `events = "logwarden-events.toml"`.
