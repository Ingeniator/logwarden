# logwarden v0.10.3

**Status:** Released 2026-11-23 · tag v0.10.3

**Outcome: the GenAI conventions cost no per-run copying.** Since v0.10.2 each check builds the
registry chain logwarden → GenAI → semantic conventions by copying about 290 files into a
temporary directory: semconv without the `gen-ai`, `mcp` and `openai` directories that GenAI
replaces (Weaver loads every file under a registry path and can't skip directories), and GenAI
pointed at that copy. Measured on a one-line check (median of 15, laptop): v0.10.1 0.244 s,
v0.10.2 0.355 s, of which about half is that copy and half Weaver loading the larger registry.

## Fixes

- **The chain is built once and cached** next to the downloaded archives
  (`<cache>/registry-semconv-<v>-genai-<v>-<format>`), per pair of pinned versions. It's built in a
  temporary directory and renamed into place, so an interrupted or parallel run never leaves a
  half-built copy. Each check copies only logwarden's own registry files (a few small files)
  and points them at the cached chain.
- **A cache copied to another directory is rebuilt there.** The GenAI manifest in the chain
  points at the semconv copy by absolute path (Weaver reads a relative path from the working
  directory), so a chain whose path doesn't match its location isn't used.
- **`logwarden setup` builds it too**, so the Docker image ships it and runs offline as any user.
- **When it can't be cached, the check works as before:** with `LOGWARDEN_SEMCONV` or
  `LOGWARDEN_SEMCONV_GENAI` set (a local directory whose content can change), or when the cache
  can't be written (a read-only cache), the chain is built in the run's temporary directory.

## Changes you might notice

- A new directory in the cache, about the size of the semantic conventions model.

## Breaking changes

None.
