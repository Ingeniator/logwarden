# logwarden v0.3.0

**Status:** Planned. Notes written before implementation, and each claim is checked below
before release.

One package and one version for every channel: PyPI, the GitHub Action and the Claude Code
plugin all ship the same logwarden.

## What's new

- **Install from PyPI.** `uv add --dev logwarden`, `pipx install logwarden`, or run it
  without installing: `uvx logwarden check logs.jsonl`.
- **The CLI is rewritten in Python.** It has the same commands (`check`, `rules`, `init`,
  `setup`), the same `--json` fields and the same exit codes (0 clean, 1 violations,
  2 usage/setup error). `jq` and `bash` are no longer needed. It runs on Linux, macOS and
  Windows.
- **Project config.** Settings go in `[tool.logwarden]` in `pyproject.toml`, or in
  `logwarden.toml` for projects without Python. v0.3.0 reads `fields`. Unknown keys produce
  a warning instead of being ignored silently.
- **pytest plugin included.** Installing `logwarden` registers the capture plugin;
  `LOGWARDEN_CAPTURE=logs.jsonl pytest` works as before.
- **MCP server included.** `logwarden mcp` (install with the `logwarden[mcp]` extra), e.g.
  `uvx --from 'logwarden[mcp]' logwarden mcp`. Same four tools as v0.2.0.
- **Claude Code plugin.** `/plugin marketplace add Ingeniator/logwarden`, then
  `/plugin install logwarden`. It provides the logwarden skill, the MCP server and the
  `/logwarden:check` command, and updates with each release.
- **GitHub Action** runs the PyPI release of the same version. Its inputs (`logs`,
  `fields`, `fail`) are unchanged.
- **Release automation.** Pushing a `v*` tag builds and publishes to PyPI with trusted
  publishing (no stored token).

## Breaking changes

- `logwarden-pytest` is replaced by `logwarden`. Uninstall it and install `logwarden`.
- `bin/logwarden`, `mcp/server.py` and `python/logwarden_pytest/` are removed from the repo.
  Use the installed `logwarden` command.
- `logwarden init --agent` no longer copies the skill into `.claude/skills/`. Install the
  Claude Code plugin instead. It still writes the `AGENTS.md` section for other agents.

## Upgrading from v0.2.0

```bash
uv remove --dev logwarden-pytest && uv add --dev logwarden
# CI: uses: Ingeniator/logwarden@v0.3.0
# Claude Code: /plugin marketplace add Ingeniator/logwarden && /plugin install logwarden
#   then delete .claude/skills/logwarden/ if init --agent created it
```
