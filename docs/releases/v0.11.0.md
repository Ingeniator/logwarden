# logwarden v0.11.0

**Status:** Planned

**Outcome: you know which log calls your tests never run.** logwarden checks the log lines
that tests write. A log call that no test reaches is never checked, and those are mostly the
calls that matter: errors and exceptions. A prototype on four ai-suite services (2026-11-23)
found that tests run 27% to 50% of the log calls, and almost none on error paths: one service's
tests run none of its 16 `error` and 4 `exception` calls, while its line coverage is 64%.

`logwarden log-coverage` reports, per file and level, which log calls the tests run, from the
coverage data a test run already produces.

## What's new

- **`logwarden log-coverage --coverage FILE [PATHS...]`** (Python source). It finds the log
  calls in the source (`log.info(...)`, `logger.warning(...)`, `self.log.error(...)`,
  `logging.exception(...)`, `structlog.get_logger().bind(...).info(...)`,
  `logger.log(logging.ERROR, ...)`), and counts a call as **reached** when the coverage data
  says the statement that contains it ran.
  - Coverage data: coverage.py's `.coverage` file, `coverage json`, or Cobertura XML
    (`coverage xml`, `pytest --cov-report=xml`). Read without extra dependencies.
  - A log call is `<receiver>.<level>(...)`, with level `debug`, `info`, `warning`, `warn`,
    `error`, `exception`, `critical`, `fatal`, `msg` or `log`, and a receiver whose text has
    `log`, `logger`, `logging`, `structlog` or `slog` as a word (`log`, `self._logger`,
    `app.logger`, not `dialog` or `catalog`). `--receiver REGEX` replaces that rule.
  - Not counted: files under `tests/`, `test_*.py`, `conftest.py`, `.venv`, `venv`,
    `node_modules`, `build`, `dist`, `migrations`; lines coverage.py excludes
    (`# pragma: no cover`). `--exclude GLOB` adds more. A source file missing from the
    coverage data counts as not reached.
- **Emitted, not just reached:** `--logs FILE` (the lines captured from the tests, e.g. with
  `LOGWARDEN_CAPTURE`) also counts the calls that wrote a log line, by `code.file.path` and
  `code.line.number`. A call can run and write nothing (a `debug` call below the log level).
  `--logs` alone, without `--coverage`, reports emitted calls only.
- **Output:** a summary (reached / total, overall and per level), the files with the most
  unreached calls, and the unreached calls as `path:line  level  receiver`; `--json` for the
  full result; `--markdown FILE` for a job summary or PR comment.
- **A CI gate, off by default:** `--fail-under PCT` exits 1 when fewer than PCT% of the
  counted calls are reached (or emitted, with `--logs`). `--levels error,exception,critical`
  counts only those levels, e.g. "every error path is tested":
  `logwarden log-coverage --coverage .coverage --levels error,exception,critical --fail-under 80 src/`.

## Changes you might notice

- A new command. Nothing else changes: `check` and its findings, `--json` keys, exit codes.
