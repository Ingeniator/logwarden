# logwarden v0.9.0

**Status:** Released 2026-11-22 · tag v0.9.0

**Outcome: a team gets its first useful result in under 10 minutes, without changing its
code.** Today a new team chooses between eight use cases and about ten ways to integrate, and its
first run on an existing service is a wall of findings in which the serious ones (secrets in
logs) get lost. Teams also hesitate to depend on a v0.x tool with one maintainer. This version
cuts the choices to one recommended path per platform, starts with the few rules every service
should pass, ranks what to fix first, adds a check of the logs a team already has in
Elasticsearch, and writes down what is stable.

`logwarden watch`, a long-running consumer of the live stream, was planned here first. It was
dropped (2026-11-22): the only team using logwarden runs it in CI only, with no shared state,
and an hourly scheduled job gives the same view with nothing to operate. It is listed under
"Later" in the roadmap.

## What's new

- **Rule profiles.** `--profile essential` (or `profile = "essential"` in the config) checks
  only what applies to any service as it is:
  - `adr_sensitive_data`: secrets and personal data in logs,
  - `adr_non_json_line`: lines that aren't JSON,
  - `adr_missing_required`: the required resource fields.

  `standard`, every rule as today, stays the default, so nothing changes for existing users.
  Under `essential` the summary says how many more findings `standard` would report, so the next
  step is visible. `disable` and baselines work with both.
- **Ranked fixes.** Findings are grouped by what causes them: the source line when the logs
  have `code.file.path`/`code.line.number`, else the logger and event. The groups are sorted by
  the number of lines they affect. The text summary, Markdown and HTML reports start with
  "Fix first": the top groups with their share of all violating lines ("the top 3 places
  cause 62% of the lines with violations"). `--json` gets new keys `fix_first`,
  `lines_with_violations`, `profile` and `outside_profile` (existing keys don't change).
- **`logwarden fetch`** writes the newest lines of a time window from Elasticsearch
  (`--es URL --index 'logs-*' --since 1h`, at most 10,000, Elasticsearch's default limit;
  `--query` narrows it down) as a `_search` response for `check`. Credentials come from
  `LOGWARDEN_ES_AUTH` (`ApiKey …`, `Basic …` or `user:password`), never from the command line.
  When more lines matched than were fetched, every report says it's a sample and of what size.
- **`check --pushgateway URL`** pushes the per-service metrics to a Prometheus Pushgateway
  (PUT, so each push replaces the group).
- **Scheduled check of production logs: results without touching the service.** A second hidden
  job in the GitLab template, `.logwarden-production`, for a scheduled pipeline (and the same
  two commands as a recipe for cron or a Kubernetes CronJob):
  - It fetches the last `LOGWARDEN_SINCE` (default `1h`) of `LOGWARDEN_ES_INDEX`, with
    `LOGWARDEN_ES_AUTH` from a masked CI variable. The fetched logs hold logged values, so they
    are kept outside the artifacts and deleted after the check.
  - It runs `check` on the response with the project's `[source]` and profile, writes the
    Markdown and HTML reports and the snapshot as artifacts, and compares with the previous
    scheduled run: new and fixed findings since the last run. The previous snapshot is kept
    in the job's cache, so pushes between two runs don't lose the comparison.
  - With `LOGWARDEN_PUSHGATEWAY` set, it pushes the metrics, grouped by project.
  - It never fails on violations (they are the result, not an error). It fails on a bad
    config, an unreachable Elasticsearch or an empty window, so a broken schedule is noticed.
  - It uses the image and works without internet access, like the merge-request job.
- **GitLab template: readable comparison names.** The merge-request job saves the target
  branch's snapshot as `<branch>-snapshot.json` (e.g. `main-snapshot.json`), so the report
  says what it compared with.
- **Grafana dashboard** `integrations/grafana/logwarden.json`: the share of lines with
  violations per service, violations by rule, and the time of the last push (a stale schedule
  shows). The panels use the values of the last push, not `rate()`, because each push is one
  window.

## Docs

- **Four "Start here" pages, one per path,** each with copy-paste steps that end in a first
  report, starting with the `essential` profile:
  - **Elasticsearch / Kibana:** the scheduled check on logs you already have. No code change.
  - **GitLab:** the template on the logs of your test run.
  - **GitHub:** the Action on the logs of your test run.
  - **AI agents:** the Claude Code plugin, or the `AGENTS.md` snippet.
- **README** leads with one sentence and the four paths. The eight use cases and the rest of
  the integration guide move under "Advanced" in the site nav. Nothing is removed.
- **`STABILITY.md`**: what is a public interface (rule ids, `--json` keys, exit codes, config
  keys, metric names, CLI options, image tags), how it changes (only additions; a removal is
  announced in the release notes, warned about for at least two minor versions and happens only
  in a major version), which versions get fixes (the latest minor), that published image tags
  are never overwritten, and the conditions for 1.0: at least two teams using logwarden for a
  month with no change to the public interface needed.

## Fixes and maintenance

- **Archive paths on Windows.** On Python 3.10 and 3.11 the downloaded Weaver and semconv
  archives are checked member by member. A name such as `/x` or `C:/x` wasn't seen as absolute
  on Windows. Every name is now checked with Windows path rules on every OS. The archives were
  already checked against a pinned SHA-256, so no download could have used this.
- **Test coverage is measured in CI** (job `coverage`), including the CLI and MCP server that
  tests start as subprocesses. Below 85% the job fails. 93% at the time of writing.

## Breaking changes

None. The default profile is `standard`, which checks what every earlier version checked.
