# logwarden v0.8.1

**Status:** Released 2026-11-22 · tag v0.8.1

GitLab support and clearer docs, from feedback by a team running logwarden on GitLab inside a
network without internet access. On GitHub, findings show up in the pull request through the
Action, SARIF and the PR comment. On GitLab, teams got only downloadable reports. Now findings
appear in the merge request, through GitLab's own Code Quality report.

## What's new

- **`--codequality FILE`** on `check` and `lint-code` writes a
  [GitLab Code Quality report](https://docs.gitlab.com/ci/testing/code_quality/). With
  `artifacts: reports: codequality`, GitLab lists new and resolved findings in the merge
  request's Reports tab (every tier). Ultimate also marks them in the diff.
  - A finding sits on the source line that logged it when the line has `code.file.path` and
    `code.line.number` (as for SARIF), else on its line in the log file. Paths are relative to
    the repository (`--source-root` strips a build prefix).
  - Fingerprints don't contain line numbers, so a finding whose code moved stays the same
    finding. Each finding has its own fingerprint, because GitLab merges identical ones.
  - Severity: `critical` for `adr_sensitive_data`, `major` for every other rule.
  - Like every report, it never contains logged values.
- **GitLab CI template** [`ci/gitlab/logwarden.gitlab-ci.yml`](https://github.com/Ingeniator/logwarden/blob/main/ci/gitlab/logwarden.gitlab-ci.yml):
  a hidden `.logwarden` job to `extends:`. It runs the Docker image (set `LOGWARDEN_IMAGE` to
  your registry's copy), compares with the target branch's snapshot, writes the Code Quality
  report and the HTML and Markdown reports, and needs no internet access. It reports and doesn't
  block: `allow_failure: exit_codes: [1]` lets violations through, but a broken setup (exit 2)
  still fails.

## Docs

- **Integration guide:** the GitLab section uses the image and the template instead of `pip install`.
- **Integration guide:** new "Without internet access" section. It explains that the package
  install and the first-run Weaver and semconv downloads are separate steps. Options:
  - the image mirrored into your registry;
  - `logwarden setup` run once where the internet is reachable, then the cache copied;
  - `WEAVER` and `LOGWARDEN_SEMCONV` pointing at local copies.
- **README and integration guide:** `configure()` is optional. The checker reads whatever JSON a
  service's own logger writes, and the pytest plugin captures through the app's own formatter.
- **Docs site:** release notes of versions not yet released are listed as "(planned)", so
  they don't look like releases.
